# 从 0.x 升级到 2.0

2.0 是重写，不是迭代。先读这一页能省掉四个坑。

## 一句话

**配置不需要你动，面板换了一个，账本换了地址。**

- 你已有的 provider 配置（地址、密钥、headers）**2.0 一个字节都不改**。
- 2.0 的账本在 `<profile>/model-sync/`（`version: 1`）。旧版的账本会被改名成 `model-sync.legacy-<时间>` 保留在原地，不会被当成新版读取。
- 面板从「另一个位置」搬到 **设置 → 模型更新**，交互与 0.12.5 一致（折叠卡片、搜索/筛选、勾选即待加入、底部保存条）。

## 四步

### 1. 装

```sh
node scripts/install.mjs --profile desktop           # 干跑，先看清楚它要改哪四处
node scripts/install.mjs --profile desktop --apply
```

装完**重启 DSH**。旧状态目录自动让位，四次引用一次写齐（少写 `pnpm.overrides` 的后果不是「不生效」，而是下次 `pnpm install` 悄悄退回旧版）。

### 2. 看一眼面板

设置 → **模型更新**。首次打开时：

- 顶部会出现「最近一次自检通过 / 发现 N 个问题」；
- 每张卡第一次显示 `待检查`，点「立即检查」；
- 检查结果里 `上游新增 N` 就是你 0.x 时代错过的新模型。

### 3. 删掉上一版的合成供应商

上一版为「协议兄弟」造了 `<base>-chat` / `-messages` / `-responses` 这些键。它们对目录内的模型是冗余的——2.0 里一条路由本来就按每个模型自己的协议走。

面板底部会显示「上一版插件留下了 N 个合成供应商」，点「删除这些合成供应商」（要点两次确认）。

只想先看看会删什么：

```sh
node scripts/rehearse.mjs      # 只读彩排：打印将要 unset 的键，并把 sha256 前后对比证明零写入
```

规则很窄：**只删「父路由仍然存在」的 `<任意名>-chat/-messages/-responses`**。父路由不在的同名键不动（那是别人手工建的）。

### 4.（可选）让需要代理的模型走代理

如果 0.x 时代你一直卡在「开了 Clash 但 Gemini 连不上」：0.x 的做法（在 harness 里装全局 dispatcher）原理上够不到模型请求的那一跳。2.0 改为往真正发请求的那个进程的策略表里写声明：

- 面板代理行的开关打开它；
- 「网络出口详情」里能看到逐域名的 `→ 代理 / 直连`；
- 只在**系统代理存在**时写，撤销只删自己写过的键。

## 0.x → 2.0 的行为差异

| 项 | 0.x | 2.0 |
| --- | --- | --- |
| 多协议路由上的新模型 | 造 `<base>-chat` 等子路由 | 目录内的模型照旧；目录外的用**协议网关**（默认关闭） |
| 让模型走代理 | 重装全局 HTTP dispatcher | 写那个进程的 `providers.<主机>.proxy` 声明 |
| 面板 | 卡片 + DOM 注入 | 卡片，**零 DOM 注入**，只占一个 `settings.section` |
| 「清空」 | 修过一次（0.12.5） | 取消整张卡的全部勾选，至少保留一个（与 0.9.6 的语义一致） |
| 协议判定 | models.dev 缓存 + 猜测 | 真请求问一次，问不到就不猜 |
| 状态文件 | 无版本闸 | `version: 1`，跨版本拒绝读、损坏则归档 |
| 删除最后一个模型 | 写空数组 | 写 `unset`（否则内置目录会整张回来） |

## 回滚

```sh
node scripts/rollback.mjs                 # 干跑：要还原哪三处、挑哪份备份
node scripts/rollback.mjs --apply         # 执行（之后重启 DSH）
node scripts/rollback.mjs --restore-state # 额外把旧版状态目录换回来
```

它只还原三处引用与符号链，不整份覆盖 manifest（那会删掉你备份之后装的其它插件），执行前自己留一份备份，所以回滚也可逆。

## 常见问题

**Q：升级后模型列表变短了？**
A：2.0 不会自动删任何模型。变短通常是 0.x 的子路由键被删除时，那些键里本来就只放了 redundant 的副本。检查面板里每张卡的「已启用 N 个」，与官方设置对照。

**Q：`deepseek-official` 显示「没有目录接口」，是不是坏了？**
A：不是。DeepSeek 官方适配器没有列举模型的接口，2.0 不发请求、也不报红。这类供应商请在官方设置里改。

**Q：`opencode` 显示「无法检查」？**
A：它的地址写在每个模型上、路由本身没有 `baseURL`。2.0 自带一张地址表（`lib/endpoints.js`）去问；如果连这张表里的地址也不通，卡片会说明原因。

**Q：我想让 2.0 完全不碰代理配置？**
A：面板代理行的开关关掉即可；关掉时它会把之前写过的键撤回原值。
